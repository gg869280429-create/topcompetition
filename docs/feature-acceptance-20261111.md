# 功能扩展交付与验收记录（2026-11-11）

## 交付边界

本轮按用户确认的 18 项需求扩展现有模块，保留原报名邀请、审核、退赛、权限及文件服务。代码尚未提交或推送。最初验收使用独立库；用户随后明确授权补齐数据库结构，已在现有本地业务库完成新迁移及管理员端复验，详见[管理员端排查与修复记录](admin-diagnostics-20261111.md)。这不表示已部署任何远程生产环境。

## 自动化验证

- `backend`：`$env:RUN_DB_TESTS='true'; mvn -o package`，**183 项测试，失败 0、错误 0、跳过 0**，连接本机 MySQL 创建的独立测试库。
- 控制器自动枚举：**88 个接口 × 5 种身份 = 440 次请求**，包含 ADMIN、MAJOR_ADMIN、TEACHER、STUDENT、未登录，无 500 错误。登录接口另外由真实账号登录场景覆盖。
- 该 440 次矩阵主要验证角色、缺参数和无效 ID；不能等同于 440 个成功业务场景。有效数据的完整业务链路及异常场景由下述集成测试另外验证。
- 业务数据迁移副本启动真实后端后，额外完成 **170 次实际 HTTP 只读请求，无 500 错误**，覆盖现有记录及新列表。
- 前端 `npm run build` 通过；后端完整测试及打包通过。随后调整 JAR 排除本地配置的规则，再次执行 `mvn -o package -DskipTests` 验证打包。

主要业务及异常覆盖：

1. 报名开始前、截止后拒绝，已有报名的赛制/规则/删除保护，状态顺序及取消原因。
2. 不允许跨专业时阻止跨专业团队；分类属于其他专业仍可按规则报名，归属队长专业审核。
3. 邀请接受、拒绝、撤销；未确认不得提交；成员重复资格及并发提交；驳回后重提保留意见。
4. 报名审核确认意向教师、调剂、名额满额和并发；已通过退赛审批、有效获奖阻止退赛、重复审批不重复释放。
5. 专业管理员不能操作其他专业，教师不能换 ID 读取无关团队，材料访问检查所属业务。
6. 教师重复完成不重复释放，结果多次保存仍一份，不自动退赛/生成获奖；已完成教师不能从其他指导快照或团队后续历史读取新成员。
7. 草稿缺材料可保存但不能提交；两张照片数量/用途校验；驳回原因和重提；共享成果及重复登记保护。
8. 成果更正保留原人员及专业快照、管理员可复用已授权的原材料，审核再次校验完整材料，未配置专业的专业管理员被拒绝。
9. 同团队两项成果、两名教师、不同获奖学生，分别统计成果数、团队数、获奖学生数及教师指导成果数；撤销后正确减少。
10. 同一成果各教师分别领取庆祝、重复领取失败、撤销过滤；取消竞赛关联报名、退赛待审、指导资格及历史处理。
11. 新闻发布、正文读取、下线、编辑、删除、轮播过滤、封面权限、非法链接及伪造材料内容。
12. 历史竞赛单独分类补录不改变终态或人数规则，并校验角色、管理权与浏览器 Origin。

完整测试名称及统计在本地 `output/feature-test-summary.json`；每角色接口结果在 `output/feature-api-*.json`；真实 HTTP 在 `output/feature-live-api-audit.json`。这些忽略的测试产物不应提交。

## 浏览器验证

使用独立迁移副本和四角色专用测试账号，未修改业务库的真实账号：

- 系统管理员可见专业/学生/教师/新闻菜单，实际新增专业、审核两项成果。
- 专业管理员没有专业管理菜单，直接进入 `/major` 被前端导向 403；后端限制由集成测试分别验证。
- 教师离线后的两项获奖庆祝依次展示，关闭并刷新不重复；教师首页有新闻轮播。
- 教师完成指导后该竞赛占用从 1 变为 0、剩余从 1 变为 2；仍可查看团队、登记学生结果。
- 实际操作学生未参赛结果保存；学生个人记录显示两条通过成果，详情区分全体名单和实际获奖人员，显示教师及材料入口。
- 学生新闻正文可阅读，官网入口具备 HTTP/HTTPS 地址及新标签属性。
- 历史已结束竞赛可通过分类入口补录专业，状态仍为已结束；教师详情单独增加名额后，总名额/占用/剩余由 2/0/2 变为 3/0/3。
