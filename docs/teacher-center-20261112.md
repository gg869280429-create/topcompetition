# 教师端及团队名单调整（2026-11-12）

## 本次规则与实现

1. 已审核通过的团队由队长调整队员，无需管理员重新审核，保留报名状态、审核意见及现有指导关系。新增学生先收到邀请，接受后才加入正式名单；拒绝、撤销均保留记录。待确认邀请不占参赛资格。接受时重新校验学生状态、专业、人数、跨专业限制与重复参赛。
2. 教师首次保存“参赛”即锁定整份报名的团队名单；后来把结果改为“未参赛”也不解锁。完成指导同样冻结当时名单。存在待确认邀请时须先处理邀请，才能确认参赛或完成指导。竞赛结束、取消，或存在待审核退赛、有效获奖记录时禁止调整队员。报名截止后，已通过团队仍可在教师确认前调整；首次报名和驳回重提继续遵守原报名时间限制。
3. 团队赛可统一登记全队参赛、获奖情况，并保留逐学生明细，随后可逐人更正结果。整队操作在一个事务中保存；结果不自动退赛或创建获奖申报。正式成果仍使用原申报模块，一项共享成果关联实际获奖人员及老师，避免重复计数。个人赛保留逐人登记。
4. 指导管理和教师个人中心展示本人剩余、正在指导、总共指导名额；汇总覆盖本人全部已配置竞赛，与分页明细一致，只有 ACTIVE 指导占用名额。完成一份指导只释放一个名额，总名额保持不变。
5. 教师“个人中心”紧邻“竞赛预览”下方，复用学生资料与密码设置，增加指导名额、已通过历史获奖、成果详情入口。“竞赛费用申报审批”仅显示“敬请期待”。师生均可从头像下拉进入本人资料；学生原五项菜单及顺序保留。

## 接口

新增以下六个方法和路径组合，继续由后端校验角色及本人范围：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/profile` | 师生本人资料 |
| PUT | `/api/profile` | 修改本人姓名、手机号、邮箱 |
| PUT | `/api/profile/password` | 修改本人密码，旧登录凭证失效 |
| GET | `/api/guidance/quota/summary` | 教师本人三项名额汇总 |
| PUT | `/api/registration/{id}/members` | 队长调整已通过团队名单、发送邀请 |
| PUT | `/api/guidance/{id}/results/team` | 教师整队批量保存参赛及获奖情况 |

保留原 `/api/student/profile` 系列学生专用接口及其权限。原调整入口与新增成员接口共用状态约束，无法绕过名单锁定。业务历史、通知与名单变更在同一事务写入。

## 数据库迁移

部署顺序：停止后端写入，完整备份并验证恢复，在已执行 04 迁移的数据库执行 `sql/migrations/20261112_05_teacher_roster.sql`，再发布后端和前端。脚本不是重复执行脚本；字段存在时应先确认迁移状态。

本地 `competition` 已执行迁移。仅增加 `registration.roster_locked_at`、`roster_locked_by`；旧数据中已有参赛结果、已完成指导或有效获奖的报名初始化为锁定。历史锁定时间标记为升级时间，教师字段留空，避免伪造原确认信息。

迁移前已创建完整备份，恢复到独立数据库并演练脚本；迁移前后对全部旧字段及记录数计算摘要比对，一致。备份、恢复库名称及校验摘要保存在本地忽略的 `output/teacher-roster-migration-result.json`，备份文件在 `output/backups/`。数据库原有业务记录未清空或覆盖。
