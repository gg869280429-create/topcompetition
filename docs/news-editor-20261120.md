# 新闻、轮播与竞赛同步发布调整

## 功能

- 新闻管理、轮播图管理与竞赛同步新闻共用 `NewsEditorDialog`，统一字段、封面上传预览、校验与新闻新增/更新接口。
- 轮播列表展示首页图片；点击“轮播设置”可更换封面、维护标题、正文、官网、排序和展示时间。
- 已发布及定时新闻可直接编辑；校验官网、封面和时间，普通换图保留发布状态及发布时间。公告、通知沿用原草稿编辑限制。
- 保存竞赛不会自动弹出新闻。仅在“发布竞赛”勾选同步新闻后进入同款新增新闻弹窗，预填竞赛标题、简介，默认开启当前时刻起两周轮播，时间可修改。
- 同步发布前必须补齐封面和官网。取消弹窗不发布竞赛，未选择同步时仅发布竞赛。

## 接口与一致性

封面继续使用 `POST /api/file/content-cover`，图片读取继续使用 `GET /api/content/{id}/cover`。新闻与轮播编辑统一调用 `PUT /api/content/{id}`，不再由前端调用只能调整轮播开关和时间的专用更新接口。旧轮播接口保留兼容。

同步新闻先通过 `POST /api/content` 保存草稿，然后通过既有竞赛发布接口提交 `syncNews: true` 与 `newsId`。后端检查草稿作者、NEWS分类及草稿状态，在同一事务中发布竞赛、新闻并记录历史。失败时竞赛发布回滚，新闻保持草稿；同一弹窗修改重试复用该草稿ID，不重复新增。

如果发布失败后关闭弹窗，已保存草稿可从新闻管理继续处理。旧版内嵌 `news` 的竞赛发布请求仍兼容；不能同时传入 `news` 和 `newsId`。定时新闻依照其发布时段进入定时状态，轮播还需满足自身展示时段。

## 验证

- 后端全量测试241项，失败0、错误0、跳过0。新增覆盖已发布新闻换图、权限及错误输入保持原值、定时调整、同步已存草稿、发布失败回滚与重试、其他作者/非新闻/非草稿拒绝等场景。
- 浏览器26项检查通过，无未捕获异常。覆盖三个入口共用弹窗、换图预览、新闻与轮播共用更新接口、师生首页读取最新封面、两周默认值、必填校验、取消、发布失败重试、普通新闻草稿及发布。
- 前端生产构建通过，仍有原有大于500kB的资源体积提示。
- 数据库测试使用本地MySQL独立测试库；浏览器交互使用受控接口数据，没有写入现有业务库或生产服务器。浏览器检查与后端真实数据库测试分别验证界面行为和业务规则。
