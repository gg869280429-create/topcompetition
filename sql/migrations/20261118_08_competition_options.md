# 08 竞赛选项迁移

依赖：先完成 01 至 07，MySQL 8。保留21张表，不执行全库初始化脚本。

1. 停止后端和其他写入，完整备份数据库，先恢复到独立库核对备份并演练迁移。
2. 确认 competition.all_majors 尚不存在，再执行 20261118_08_competition_options.sql；该脚本只执行一次。
3. 对比迁移前后的原字段、行数和原规则，确认没有改写旧数据，再部署本轮前后端。
4. 验证全部专业发布、原单专业发布、双赛制创建及独立报名、教师名额、权限和旧跨专业设置。

新增 all_majors 默认为0：旧 major_id 为空表示尚未分类，仍需补录；明确选择全部专业时为1且 major_id 为空。全部专业仍只是展示分类，不改变报名归属和审核权限。

allow_cross_major 的数据库默认值改为1，只影响新插入且未指定该字段的记录；旧记录中的0或1保持不变。后端与新增表单同样默认允许跨专业，编辑保留原值。

双赛制通过同一事务创建两条 competition 记录，教师名额分别保存；不增加表，不修改旧报名结构。同一学生可在不同竞赛ID分别报名，各条记录独立发布、审核、修改状态和统计。

回退旧应用可保留新增字段；不要直接删除字段或恢复覆盖整个库。涉及丢弃新增数据的回退须另行确认。

本次仅迁移本地 competition 库，其他环境需要单独安排迁移和部署。
