# 07 管理功能整合迁移

依赖：先完成 01 至 06。适用于 MySQL 8；此脚本只能执行一次，不要对已有表重新执行 init.sql。

## 上线步骤

1. 停止后端及其他数据库写入，完整备份数据库与上传文件；先在独立恢复库验证备份可恢复。
2. 检查 sys_user.class_name、sys_major.icon_code / logo_file_id、content 的四个新时间字段尚不存在；发现已存在时先核对迁移状态，不要重复执行。
3. 在恢复库演练 `20261118_07_admin_panel.sql`；核对原表行数及原字段数据保持不变。
4. 对目标库执行同一脚本，再部署本轮后端和前端。迁移增加 7 列和 2 个索引，不删除或重写业务数据。
5. 启动后验证登录、学生班级筛选、教师名额维护、专业图标与 Logo、定时发布和轮播到期，以及原报名和指导流程。

## 兼容规则

- 旧学生的班级为空，由管理员按真实班级补录；专业管理员继续仅管理本专业。
- 旧专业没有图标配置时按专业名称匹配预设图标；自定义 Logo 使用统一文件服务，优先于预设图标。
- 原指导和名额数据不迁表。教师业务改从个人中心“我的指导”进入；管理员在教师库编辑中按竞赛维护名额，在报名管理分配老师。
- 旧新闻的四个时间字段为空，延续立即发布、长期有效。新闻仍须手动点击发布；未来开始时间进入 SCHEDULED，后台每 15 秒推进状态。
- 新闻、详情、封面和轮播读取均校验新闻展示时段；轮播还须满足独立轮播时段。结束时刻不再可见，轮播到期后关闭开关，新闻下线后不展示轮播。已打开首页每 15 秒刷新轮播数据。
- 手动下线会取消该条新闻的待发布计划；重新设置时间后需再次发布。

## 回退

如需回退应用版本，保留新增列和索引即可，原字段兼容旧版本；不要通过删列回退，以免丢失本轮新增信息。恢复旧备份会覆盖新写入数据，必须另行确认并安排维护窗口。

本次仅已执行本地 competition 库迁移；其他环境需要按上述流程单独部署。
