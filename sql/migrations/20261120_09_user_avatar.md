# 09 用户头像迁移

只新增 `sys_user.avatar_url VARCHAR(1024) NULL`，保留21张表及已有业务数据。旧用户该字段为空，前端继续显示姓名首字头像。该字段保存 OSS 稳定地址，禁止保存带临时签名的 URL。

新数据库使用最新 `sql/init.sql`；只有一个系统管理员的新生产库使用最新 `sql/production/competition-test.sql`。两份初始化脚本均已包含头像字段，不再执行09。

已有数据库升级：

1. 停止写入，备份数据库及原本的附件目录，在独立恢复库验证备份并演练。
2. 检查字段是否存在：

   ```sql
   SELECT column_name FROM information_schema.columns
   WHERE table_schema=DATABASE() AND table_name='sys_user' AND column_name='avatar_url';
   ```

3. 字段不存在时，在目标库执行一次 `20261120_09_user_avatar.sql`。它不是重复执行脚本，不会自动运行。
4. 比对原字段值、用户数及其他业务记录，随后部署对应后端和前端。
5. 填写私有 OSS 配置后验证本人上传、头像展示及失败时旧头像保持；未启用 OSS 时业务可正常使用，上传返回明确提示。

本机 `competition` 已完成备份、恢复演练、迁移及原有字段/行数一致性检查。备份和检查报告在被 Git 忽略的 `output/backups/`、`output/user-avatar-migration-result.json`。未修改远端数据库。

回退应用可保留这个可空字段。不要为回退直接删除列、覆盖旧库或删除 OSS 对象；这些操作会丢弃后续上传信息，应另行处理。
